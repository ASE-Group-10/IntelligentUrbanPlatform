# C09 / C10 contracts

Source of truth for the UC09/UC10 interfaces (see `C09_C10_Contract_UC09_UC10.docx`, v0.1 draft). Tracked in #13.

- `examples/*.json`: one file per request/response. Test doubles for other pairs return these files.
- Typed Pydantic v2 models live in the backend, next to the components that own them. JSON is camelCase, Python is snake_case. Unknown fields are rejected.
  - `backend/app/shared/c09_c10_common.py`: AuthContext, Outcome, ErrorBody, RunScope and shared enums
  - `backend/app/components/c09_logistics_knowledge/contracts.py`: C09 models
  - `backend/app/components/c10_decision_records/contracts.py`: C10 models
- `backend/tests/test_c09_c10_contracts.py`: every example must validate and round-trip; it also checks a few rules that must fail, such as evidence without content or a reason citing unknown evidence.

```bash
cd backend
uv run pytest tests/test_c09_c10_contracts.py
```

The examples and the Word document are both generated by `build_contract_doc.js`. Edit that script, then regenerate both, so they cannot drift apart:

```bash
npm install docx@9
node contracts/c09_c10/build_contract_doc.js contracts/c09_c10/C09_C10_Contract_UC09_UC10.docx contracts/c09_c10/examples
```

Changing a field means a major or minor contract version (doc §3). A major change needs consumer approval on the PR.
