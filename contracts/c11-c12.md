## Conventions and access boundary

Reuse `app.shared.contracts.ContractModel`, `UtcDatetime` and `EventEnvelope`.
JSON uses camelCase, UUID v4 identifiers and UTC timestamps; unknown fields fail
validation. Entity event versions and `schemaVersion` remain separate. This proposal
does not change the common envelope. Ranges are half-open `[start, end)`.

Every public operation receives C02-authenticated context outside its request body.
The provider, role, area and resource scope must be checked server-side on queries,
breakdowns, run listing, replay start/control and C10 selectors. A requested scope is
not an access grant. Recheck session ownership on every command. Trusted internal
event handlers check producer identity, event type/version and authorised run scope.
These models validate shape only; they do **not** implement authorisation.

## C11: KPI Analytics / UC11

| Service operation | Input | Normal result and guarantees |
| --- | --- | --- |
| `consumeOperationalEvent(event)` | Agreed producer `EventEnvelope` | Projection cursor; deduplicate eventId atomically with read-model update. Track source/coverage. Never execute an operational command. |
| `queryKPIs(context, scope, metricDefinitionVersion)` | `KPIQuery` | `KPISet` containing current, partial or stale indicators; explicit scope, units, coverage, time and definition version. |
| `getKPIBreakdown(context, metricId, scope)` | Metric and same authorised scope/version | `Breakdown`: bounded supporting records/aggregates, source event IDs, optional nextCursor. No cross-provider details. |

`AnalysisScope` contains period, providerId, optional areaId/resourceIds, scope and
runId. Simulation requires runId; live forbids it. Never mix live and simulated
populations in one aggregation. Return a typed invalid/forbidden/unavailable
failure through the existing `Result` convention when a query cannot be answered.
Requested definition versions must exist; do not silently substitute a new formula.

Each `Indicator` carries metricId, nullable value, unit, status, coverage,
lastUpdated, estimated and optional estimationBasis/reason. Coverage counts mean:
eligible population, observed members of that population, and separately excluded
records. `observed <= eligible`; exact population and exclusion rules are versioned
configuration decisions, not fixed by the architecture.

- Missing data: value **null**, status unavailable and explicit reason, never zero.
- A real measured zero is valid when observations exist.
- Incomplete coverage: partial; do not claim complete coverage.
- Estimates require a versioned basis (rates/factors/model), never a measured label.
- Trends use period-specific indicators with the same units and definition version.
- Refresh failure: return the last successful values and original lastUpdated times,
  mark the set stale and expose the failure. If there is no previous result, return
  unavailable; do not fabricate a cache. generatedAt is response time, not source time.
- Monitoring and breakdowns cannot update plans, allocations or resource commitments.

Initial metric families are delivery time, cost, congestion and environmental
impact. **No production formulas, weights, cost rates, emissions factors or freshness
thresholds are approved here.** The fixture's seconds/EUR examples illustrate shape,
not an agreed calculation. Sources/units/denominators must be agreed with C04/C05/C06/C08.

## C12: Simulation and Replay / UC12

| Service operation | Input | Result / required behaviour |
| --- | --- | --- |
| `startSimulation(context, scenario, seed, configurationVersion, key)` | `SimulationRequest` | Persist isolated run manifest/configuration/initial state before generation. Same provider/key/body returns same run; changed body conflicts. |
| `recordSimulationEvent(runId, event)` | `RecordingRecord` | Durable run-local recording cursor; deduplicate eventId. Persist full ordered outcomes, independent of coalesced city notifications. |
| `listRuns(context, filters)` | Authorised provider, scenario, status, period and bounded page cursor | Run manifests plus available ranges; listing must not leak another provider's runs. |
| `startReplay(context, runId, range, speed)` | `ReplayRequest` | Ready/paused private session and initial `ReplayFrame`; otherwise `CannotReplay(reason, availableRanges)`. |
| `controlReplay(context, sessionId, command, cursor)` | `ReplayControl` | Actual frame/status. Validate expectedCursor, session scope, target and state transition before mutation. |
| `advanceReplay(sessionId, expectedCursor)` | Trusted internal session and cursor | Next recorded frame, same cursor on read interruption; completed at range end. |

The manifest identifies provider/run, scenario, seed, configuration version,
initial-state reference/hash, recording status, availableRanges and lastSequence.
References and digest strings in the examples are placeholders, not real objects or
verified hashes. The runtime must retain immutable versioned scenario/configuration,
generator version and deterministic inputs, and verify object integrity on loading.
Seed alone is not a reproducibility guarantee.

Recording sequence is one-based and contiguous per run; cursor is the last applied
sequence (zero means initial state). A checkpoint identifies the state *after* its
cursor. Apply source outcomes by sequence, even for equal simulation timestamps.
Duplicate recording returns its original receipt; conflicting duplicate ID/sequence
fails. Never replace a source record with a coalesced `CityStateUpdated` notification.

Replay must load a checkpoint at/before the requested start and every essential
record through the selected range. Missing checkpoints/configuration/events make
that range unreconstructable. Return available ranges and do not start a partial
session pretending success. Once started, interrupted reads pause with the last
successfully committed state/cursor; resume applies the next event exactly once.

### Timeline semantics (proposed)

| Command / state | Behaviour |
| --- | --- |
| play from ready | playing |
| pause from playing | paused; retain state/cursor |
| resume from paused | playing; retry next unread event |
| seek from ready/playing/paused | Reconstruct from saved checkpoint to target within selected range, then paused. targetCursor required only for seek. |
| stop from active session | stopped; return final run/range/results metadata |
| natural range end | completed; return final metadata |
| stale expectedCursor or invalid transition | Conflict/Invalid; no cursor change |
| source interruption | paused; original cursor/state and explicit interruption |

Speed is presentation pacing only, not rerunning the simulation. The proposed
positive finite limit of 16x needs C01 agreement. A seek never reruns today's planner.

Replay uses recorded decisions and recorded KPI values, not present-day C11
calculations or C09 retrieval. Send `DecisionSelector(runId, decisionId)` to C10 and
use original saved evidence; show missing evidence explicitly. No invented history.

### Isolation is a deployment requirement

Simulation generation may use isolated simulated adapters; playback cannot generate
new operational activity. Replay has read-only recorded-data access, separate writable
session storage, and **no** credentials/network route for live plan/resource writes,
vehicle commands, agent negotiation or broker publication. Models alone do not prove
this: integration tests must demonstrate denied writes/publication using real replay
credentials before the capability is called integrated.

Use existing service `Result<T> = Ok<T> | Failure` conventions for generic Invalid,
Forbidden, NotFound, Conflict and Unavailable outcomes; do not invent an HTTP error
envelope here. `CannotReplay`, partial KPIs and paused frames are typed domain
outcomes. Public HTTP endpoints, transport envelopes, source payload schemas,
projection/recording cursor receipts and session-list DTOs are **not yet agreed or
implemented**; this increment supplies the shared value models/examples for review.
Runtime implementations must add payload-specific validation, replay transition and
cross-record sequence/checkpoint/range checks, durable idempotency and authorisation.

UTC ranges, schema drift, run isolation, speed, seek and cursor validation. They do
not prove event deduplication, persistence, authentication, recovery or broker ACLs.
Those are acceptance tests for the following implementation stories.

## Database integration rules (17 November update)

This proposal adds no SQL migration and changes no database. For implementation:

- Use the shared `docker-compose.yml`, `.env.example` and `database/README.md`
  from develop. Add only agreed component-specific settings; do not replace them.
- PostgreSQL schema proposals are `c11_kpi_analytics` and
  `c12_simulation_replay`; confirm these names with the database owner first.
  Each component creates and writes only its own schema. Read operational data
  through the owning component's interface, not direct cross-schema table reads.
- Generate UTC-stamped SQL files with `docker compose run --rm dbmate new`
  under `database/migrations/`. Include both `-- migrate:up` and a working
  `-- migrate:down`. Do not create a parallel `supabase/migrations/` history.
- Before proposing a migration, test local up, rollback, then up again. Do not
  edit files already merged to develop; add a new migration for later changes.
- Migrations require normal feature-PR review outside the implementing pair.
  Bruno applies merged develop migrations to shared Supabase and reports status.
  Do not change shared tables manually in the Supabase Table/SQL Editor.
- Keep real connection strings in ignored `.env` or the team secret store.
  C12 playback must use a separate restricted read role for recorded data and
  separate writable session storage; owned-schema conventions alone do not prove
  replay cannot modify live state or publish commands.
- Future C11 read-model/receipt migrations and C12 manifest/event/checkpoint/
  session migrations must agree retention, keys and access roles before DDL.
  No schema name, table design or production permission is approved by this doc.
