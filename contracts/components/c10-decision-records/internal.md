# C10 Decision Records and Explanation: internal interfaces

C10 stores decision-time evidence and explains saved decisions (UC10). The HTTP
operations used by the browser (C01) are in `openapi.yaml`. This file covers the
calls other components make inside the backend process.

Typed models: `backend/app/components/c10_decision_records/contracts.py`, shared
types in `backend/app/shared/c09_c10_common.py`.
Draft v0.1, owned by Qingyuan + Bangchen (#13).

Conventions: JSON is camelCase, timestamps are UTC ISO 8601 with `Z`, IDs are
UUID v4, unknown fields are rejected. Every call returns `Result<T>`: `Ok` or a
failure kind `Invalid`, `Forbidden`, `NotFound`, `Conflict`, `Unavailable`, with
a `C10.*` code.

## Shared parameter: AuthContext

Built by the caller from the authenticated request; IDs alone never grant access.

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `principalId` | string | yes | User ID or `service:<name>` |
| `principalType` | enum | yes | `User` / `Service` |
| `roles` | array of string | yes | e.g. `Service:C05`, `LogisticsOperator`, `Analyst` |
| `scope` | object | no | `{providerIds?, zoneIds?}`; absent means no provider/zone limit |
| `correlationId` | UUID | yes | Carried through one user operation |

## Provided interfaces

### recordDecision(conn, ctx, record: DecisionRecord) → Result\<RecordDecisionResponse\>

Called by **C05** (plans, replans) and **C08** (allocations, negotiations) when
they save a decision. It runs **inside the caller's database transaction** on the
caller's connection and never commits: if the caller rolls back, the decision and
its evidence are rolled back too. Records are insert-only.

Examples: `examples/record-decision-request.json` (plan selected),
`examples/record-decision-data-unavailable-request.json` (failed UC03 attempt,
no plan yet), `examples/record-decision-response.json`.

C05 owns the commit or rollback. For UC07 the revision, the decision record and
the `PlanReady` outbox entry commit together.

**Request: DecisionRecord**

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `decisionId` | UUID | yes | Generated by the caller |
| `idempotencyKey` | string | yes | Suggested `<producer>:<subjectType>:<id>:v<version>`; without a version `<producer>:PlanningAttempt:<attemptId>` |
| `decisionType` | enum | yes | `PlanGenerated` / `Replan` / `Allocation` / `Negotiation` |
| `producer` | enum | yes | `C05` / `C08`; must match the calling service |
| `decidedBy` | string | yes | Principal (agent or user) that decided |
| `subject` | object | yes | `{type, id, version}`; `type` = `Plan` / `Allocation` / `Negotiation` / `PlanningAttempt`. `version` is null when no saved version exists (always for `PlanningAttempt`) |
| `attemptOutcome` | enum | yes | `Selected` / `Infeasible` / `DataUnavailable` (UC03) / `NoChange` / `ReviewRequired` (UC07) |
| `relatedDecisionId` | UUID or null | yes | Previous decision; required for `Replan` |
| `inputVersions` | object | yes | `{deliveries[{id,version}], resources[{id,version}], citySnapshotVersion, corpusVersion}` actually used |
| `selectedOption` | object or null | yes | `{optionId, summary, details}`; required for `Selected`, null otherwise. Never invented for a failed attempt |
| `consideredAlternatives` | array | yes | Only options really considered: `{optionId, summary, metrics?, rejectedReason, evidenceRefIds[]}` |
| `reasons` | array (≥1) | yes | `{reasonId, text, evidenceRefIds[]}` |
| `predictedEffects` | object | no | `{etaMin?, distanceKm?, costEur?, co2Kg?}`, estimates |
| `evidenceSnapshots` | array | yes | C09 `EvidenceSnapshot`s passed through unchanged; may be empty with a limitation |
| `limitations` | array of string | yes | E.g. `knowledge unavailable` |
| `runScope` | object | yes | `{mode: Live/Simulation, runId}`; `runId` required for Simulation |
| `decidedAt` | timestamp | yes | |

Rules checked by the model:

- Every `evidenceRefIds` entry must be a `passageId` inside `evidenceSnapshots`.
- A `Selected` decision has a `selectedOption` and a saved `subject.version`;
  other outcomes have neither option nor invented version.
- **One corpus version per decision:** all `evidenceSnapshots` share
  `inputVersions.corpusVersion` (null when no knowledge was used). If the corpus
  changes between C05's queries, C05 re-queries before deciding.
- No `Selected` decision on a snapshot with `ruleCoverage: Incomplete`.

**Response: RecordDecisionResponse**

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `decisionId` | UUID | yes | Original ID, also on a duplicate |
| `recordedAt` | timestamp | yes | |
| `duplicate` | boolean | yes | `true` when the same key and body were recorded before |

**Failures**

| Kind | Code | When | Caller action |
| --- | --- | --- | --- |
| `Invalid` | `C10.MISSING_FIELD` | Missing field or bad enum | Fix the record |
| `Invalid` | `C10.EVIDENCE_REF_MISSING` | A reason/alternative cites a refId not in the snapshots | Fix the record |
| `Invalid` | `C10.EVIDENCE_CONTENT_MISSING` | A snapshot item has no `content` | Pass C09's snapshot unchanged |
| `Forbidden` | `C10.PRODUCER_MISMATCH` | `producer` differs from the calling service | |
| `Conflict` | `C10.IDEMPOTENCY_MISMATCH` | Same key, different body | Roll back |

### recordOutcome(conn, ctx, outcome: AuditOutcome) → Result\<AuditId\>

Called by **every component** for each protected write, including rejected ones.
Runs in the caller's transaction; a rejected operation is recorded in its own
short transaction. `principalId` and `correlationId` come from `ctx`.

Examples: `examples/record-outcome-request.json`,
`examples/record-outcome-response.json`.

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `operation` | string | yes | `<Component>.<operation>`, e.g. `C04.submitDeliveryRequest` |
| `outcome` | enum | yes | `Ok`, `Invalid`, `Forbidden`, `NotFound`, `Conflict`, `Unavailable`, `Infeasible`, `Partial`, `Unconfirmed` |
| `targetIds` | array of string | yes | Affected entity IDs; may be empty |
| `occurredAt` | timestamp | yes | |
| `details` | object | no | Never secrets, tokens or unnecessary personal data |

Response `AuditId`: `{auditId: UUID}`.

### Run-scoped explanation for C12 replay (UC12)

C12 calls the same operations as the HTTP API in `openapi.yaml`, in process:
`getDecision`, `getDecisionEvidence` and `explainDecision`, with the same request
and response models. During replay C12 must pass its `runId` with the
`decisionId` (`DecisionIdSelector {decisionId, runId}`); C10 answers `NotFound`
(`C10.DECISION_NOT_FOUND`) unless the decision was recorded in that run, so a
replay can never read another run's decisions. Explanations use only evidence
saved at decision time; C10 never queries today's C09 corpus.

Example: `openapi.yaml` → `components.examples.C10ExplainDecisionReplayRequest`.

## Required interfaces

None. C10 does not call other components; explanation text comes from an
external language-model API, with a structured fallback when it is unavailable.
